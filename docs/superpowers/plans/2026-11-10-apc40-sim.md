# APC40 mkII Browser Simulator Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Browser app in `tools/apc40-sim/` that looks and behaves over Web MIDI like a connected Akai APC40 mkII.

**Architecture:** Pure protocol modules (`controls`, `device`, `leds`, `clock`, `describe`) hold all behaviour and are unit-tested with `node --test`. A thin browser layer (`panel` SVG renderer + input, `midi` Web MIDI wrapper, `main` wiring + monitor) has no protocol logic. Messages are plain `number[]` byte arrays everywhere.

**Tech Stack:** Plain HTML/CSS/JS ES modules, no build, no dependencies. Node ≥ 18 only for tests. Chrome/Edge Web MIDI.

**Spec:** `docs/superpowers/specs/2026-11-10-apc40-sim-design.md` — every value (notes, CCs, channels, colour table, ring tables, SysEx bytes, mode rules) comes from there. Read it fully before your task.

## Global Constraints

- Do not modify anything under `src/` (the Rust router) or `configs/`.
- All files under `tools/apc40-sim/`, except `docs/router-known-issues.md`.
- No npm dependencies, no build step. `tools/apc40-sim/package.json` is `{"type":"module","private":true}` only (plus a `test` script).
- Test command from repo root: `node --test tools/apc40-sim/test/`
- Message bytes are `number[]`; functions returning messages return `number[][]` (possibly empty).
- Channel = 0-based nibble. Status bytes: Note On `0x90|ch`, Note Off `0x80|ch`, CC `0xB0|ch`.
- Behaviour the PDF does not define gets a `// unverified` comment (see spec).
- UI text in English. No localStorage, no persistence.

## Review Focus

1. Track Select in mode 0 sends no note but must send the knob dump CC 0x10-0x17 on the new bank channel — the router's bank detection depends on it (Task 3 test `track select dumps device knobs`).
2. Note On with velocity 0 from the host must turn an LED off, same as Note Off (Task 4 test `note on vel 0 is off`).
3. Host LED for track notes 0x30-0x34/0x42 on channel 8-15 (the router sends ch 12 there) must be ignored with a warning, never throw (Task 4 test `track led on ch 12 warns`).
4. Knob values clamp at 0 and 127 and send nothing when the clamped value does not change (Task 3 test `knob clamps and stays silent at limit`).
5. Truncated or unknown messages (1-byte, unknown SysEx, running status) must not throw (Task 4 test `garbage input warns`).

  /** @typedef {{ value:number, secondary:number, anim:'none'|'oneshot'|'pulse'|'blink', period:number, since:number }} LedState */
  export class Device {
    mode: 0|1|2; bank: number /* 0-8 */;
    reset(): void                         // spec "Startup state"; constructor calls it
    press(id: string): number[][]
    release(id: string): number[][]
    setValue(id: string, v: number): number[][]   // faders, crossfader, knobs; clamp 0-127; [] if unchanged
    turn(id: string, delta: number): number[][]   // knobs → setValue(value+delta); tempo/cue → one relative CC per call, delta clamped to -64..63, [] for 0

    value(id: string): number             // banked knobs: current bank
    ring(id: string): { type: number, value: number }
  }
